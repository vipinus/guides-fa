# ۰۵ · چطور سرور Linux و ابزارهای خط فرمان را از خط عبور دهیم

در Linux دو راه برای وصل شدن به خط هست؛ بر اساس نیازتان انتخاب کنید. برای اینکه کل دستگاه از خط عبور کند (گرفتن ایمیج‌های Docker، اجرای سرویس‌هایی که شبکهٔ خارج لازم دارند، کار بدون حضور شما)، از OpenVPN استفاده کنید: یک فایل پیکربندی که در ‎/etc/openvpn/client/‎ قرار می‌گیرد و با روشن شدن سیستم راه می‌افتد. برای اینکه فقط چند دستور از خط عبور کنند (git، pip، npm، curl)، از پروکسی وب استفاده کنید: آدرس پروکسی را در متغیر محیطی http_proxy بگذارید و بقیهٔ ترافیک دست نمی‌خورد. در Linux دسکتاپ می‌توانید آن را در NetworkManager هم وارد کنید. این مقاله هر سه را پوشش می‌دهد، به‌علاوهٔ نوشتن فایل رمز و دستورهای بررسی.

## راه اول: کل دستگاه از خط (OpenVPN)

1. کلاینت را نصب کنید: در Debian / Ubuntu ‏sudo apt install openvpn، در Fedora ‏sudo dnf install openvpn، در Arch ‏sudo pacman -S openvpn.
2. وارد این سایت شوید و در صفحهٔ OpenVPN روی پرچم یک منطقه بزنید تا ‎.ovpn دانلود شود. پیکربندی‌ای که Linux می‌گیرد نام کاربری و رمز را درون خودش ندارد (NetworkManager فایل‌هایی را که اطلاعات ورود درونشان است نمی‌پذیرد)، پس یک فایل رمز جداگانه بسازید: دو خط، اولی ایمیل شما در این سایت و دومی رمزتان، با chmod 600.
3. فایل ‎.ovpn را در ‎/etc/openvpn/client/<region>.conf کپی کنید و مسیر فایل رمز را در همان فایل جلوی auth-user-pass بنویسید.
4. sudo systemctl enable --now openvpn-client@<region>. وضعیت را با systemctl status openvpn-client@<region> ببینید و بررسی کنید که curl -s https://ipinfo.io/country منطقه‌ای را که انتخاب کردید نشان دهد.
5. برای عوض کردن منطقه، پیکربندی دیگری دانلود کنید و unit دیگری را فعال کنید؛ هر بار فقط یکی را اجرا کنید.

## راه دوم: فقط ابزارهای خط فرمان از خط (پروکسی وب)

آدرس پروکسی‌ای که صفحهٔ پروکسی وب این سایت می‌دهد را همراه نام کاربری و رمزتان می‌شود مستقیم در متغیرهای محیطی گذاشت: export https_proxy=https://username:password@proxy-address export http_proxy=$https_proxy. نویسه‌های خاص در رمز باید URL-encode شوند. بعد از آن، در همین ترمینال curl، wget، git، pip و npm همه از خط عبور می‌کنند و برنامه‌های دیگر تأثیری نمی‌پذیرند.

سرویس Docker (daemon) متغیرهای محیطی پوسته را نمی‌خواند؛ آن را در Environment=‎ فایل ‎/etc/systemd/system/docker.service.d/proxy.conf بنویسید و docker را ری‌استارت کنید. برای apt، خط Acquire::https::Proxy را در ‎/etc/apt/apt.conf.d/proxy.conf بنویسید.

در این راه، از اساس اتصالی وجود ندارد که قطع شود؛ دسترسی root نمی‌خواهد و مسیرها (route) را عوض نمی‌کند. برای سرورهای شرکت و وقتی فقط می‌خواهید دانلودها سریع‌تر شوند مناسب است؛ فقط روی برنامه‌هایی اثر دارد که متغیرهای پروکسی را رعایت می‌کنند و بقیهٔ ترافیک دست نمی‌خورد.

## راه سوم: NetworkManager در Linux دسکتاپ

1. network-manager-openvpn-gnome را نصب کنید (در صفحهٔ OpenVPN این سایت با یک کلیک می‌شود مرکز نرم‌افزار را باز کرد).
2. Settings (تنظیمات) ← Network (شبکه) ← VPN ← «+» ← Import from file (وارد کردن از فایل)، فایل ‎.ovpn را انتخاب کنید، ایمیل و رمزتان در این سایت را وارد و ذخیره کنید.
3. VPN را از نوار بالا یا سینی سیستم روشن و خاموش کنید. برای اتصال خودکار هنگام روشن شدن سیستم، در تنظیمات اتصال سیمی/بی‌سیم گزینهٔ «Automatically connect to VPN» (اتصال خودکار به VPN) را تیک بزنید.

## بررسی و عیب‌یابی

- بررسی خروجی: کشوری که curl -s https://ipinfo.io نشان می‌دهد همان منطقه‌ای است که انتخاب کرده‌اید.
- بررسی DNS: در resolvectl status، DNS رابط VPN باید همانی باشد که خط فرستاده؛ اگر نشت دارد، dhcp-option DNS را به پیکربندی اضافه کنید یا از اسکریپت update-systemd-resolved استفاده کنید.
- AUTH_FAILED: فایل رمز اشتباه است یا حساب منقضی شده؛ اگر رمزتان را عوض کرده‌اید، فایل رمز را به‌روز کنید.
- TLS handshake timeout: ترافیک UDP به سرور نمی‌رسد؛ منطقه یا شبکه را عوض کنید. روی سرور ابری، security group باید UDP خروجی را مجاز کند.
- سرور در چین است و منابع چینی باید مستقیم وصل شوند: وقتی OpenVPN وصل است، همهٔ ترافیک خروجی از خط عبور می‌کند. منابع apt / pip / npm را روی mirrorهای چینی بگذارید، یا به جایش از راه دوم استفاده کنید تا فقط دستورهای مشخصی از خط بروند.

## نکته‌هایی که باید بدانید

- هر دستگاه Linux یک دستگاه حساب می‌شود و سهمیهٔ آنلاین هم‌زمان را با دستگاه‌های دیگرتان شریک است (شخصی ۲ دستگاه، خانوادگی ۴، سازمانی ۸)؛ پروکسی وب در راه دوم هم بر اساس اتصال شمرده می‌شود و در همین سهمیه است.
- فایل پیکربندی و فایل رمز حکم خود حسابتان را دارند؛ آن‌ها را در مخزن git نگذارید و داخل ایمیج قرار ندهید.
- بعد از عوض کردن رمز، پیکربندی قدیمی بلافاصله از کار می‌افتد؛ این سازوکار باطل کردن، عمدی است. به‌روز کردن فایل رمز کافی است.
- اگر خط را روی سرور ابری اجرا می‌کنید، شرایط استفادهٔ ارائه‌دهندهٔ سرور را رعایت کنید؛ خط فقط مدت اتصال و حجم کل ترافیک را ثبت می‌کند.

## پرسش‌های رایج

**چرا پیکربندی Linux نام کاربری و رمز را درون خودش ندارد؟** NetworkManager هنگام وارد کردن، فایلی را که اطلاعات ورود درونش است نمی‌پذیرد و خطای وارد کردن می‌دهد؛ برای همین نسخه‌ای که برای Linux داده می‌شود از شما می‌خواهد خودتان پرشان کنید؛ در روش systemd آن‌ها را در فایل رمز بنویسید.

**می‌شود فقط Docker از خط عبور کند؟** بله: متغیرهای پروکسی را فقط برای سرویس Docker تنظیم کنید (راه دوم)؛ یا یک کانتینر دارای OpenVPN (gluetun) اجرا کنید تا کانتینرهای مشخصی از خط عبور کنند.

**«خصوصی» (Tailscale) روی Linux چطور؟** اسکریپت رسمی با یک خط نصبش می‌کند و tailscale up --login-server=<سرور کنترل این سایت> وارد می‌شود. برای وقتی مناسب است که باید از بیرون به این دستگاه دسترسی داشته باشید، یا می‌خواهید یک بار تنظیم کنید و همیشه آنلاین باشد؛ اگر فقط سریع‌تر شدن دانلودها را می‌خواهید، OpenVPN یا پروکسی ساده‌تر است.

**برای OpenWrt روی روتر هم همین است؟** روی OpenWrt بستهٔ luci-app-openvpn را نصب کنید و ‎.ovpn را بارگذاری کنید تا کل شبکهٔ محلی از خط عبور کند؛ روتری که فریمور این سایت را دارد به این کار نیاز ندارد، فقط وارد حسابتان شوید.
